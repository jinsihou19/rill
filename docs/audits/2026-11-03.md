日期：2026-11-03（Asia/Taipei）。基线提交：`0cc3007`，本轮源码版本：v0.2.5 / build 7。

**What this repo does:** rill 是单用户使用的原生 macOS Redis 工作空间，覆盖 standalone 实例的浏览、编辑、命令、诊断和单键导出。审核按交互式客户端负载判断，重点检查数据安全、异步状态、受限读取和失败语义，不假设已经通过生产规模性能验收。

## Must fix：本轮已修复

### 1. [P1] 创建键的 TTL 失败会留下永久键

- **位置：** [`RedisDatabase.create`](../../Sources/RillCore/RedisDatabase.swift)。
- **作用：** Lua 检查同名键后，创建指定类型，再设置过期时间。
- **问题：** Redis Lua 出错不会回滚先前写入。账户有创建权限但没有 `PEXPIRE` 权限，或 TTL 相加超过服务器绝对时间范围时，界面报错，但新键已存在且没有 TTL。六种数据类型均在真实临时 Redis 中复现。
- **修复：** 在同一 Lua 脚本中，先对尚不存在的目标执行过期权限和参数检查，再创建和设置 TTL。
- **若保留原行为：** 本应自动失效的数据会永久驻留，重试创建又因同名键存在而失败。
- **验证：** 两项真实 Redis 回归分别覆盖六种类型的权限拒绝和溢出；原实现失败，修复后目标键均保持不存在。已有创建、TTL、冲突和只读测试继续执行。

### 2. [P2] 搜索切换后旧详情读取状态不释放

- **位置：** [`AppModel.loadKeys`](../../Sources/RillApp/AppModel.swift)。
- **作用：** 切换查找条件时废弃旧选择，并用代次检查拒绝旧详情响应。
- **问题：** 详情读取中提交新搜索，旧响应被正确丢弃，但 `isLoadingDetail` / 停止状态没有清理；新搜索完成后工作区仍持续忙碌，写入、切库和刷新保持禁用。
- **修复：** 废弃选择时同时暂停旧成员会话、释放其引用和加载 / 停止状态；已发出的响应仍正常读取完成。
- **若保留原行为：** 弱网下切换搜索可能把工作区留在无法继续操作的状态。
- **验证：** 应用状态测试执行“选择键 → 详情尚未完成 → 新搜索”；原实现持续 busy，修复后结果为空且所有旧读取标记已释放。

### 3. [P2] 界面写入断线缺少结果未知提示

- **位置：** [`RedisConnection.fail`](../../Sources/RillCore/RedisConnection.swift)、[`AppModel.mutate`](../../Sources/RillApp/AppModel.swift)。
- **作用：** 将网络和协议失败传播给界面写入入口。
- **问题：** 命令工作台会解释写入结果未知，但可视化编辑收到连接关闭时只显示普通断线消息，无法判断服务端是否已执行。随后到达的断线回调还可能覆盖具体操作错误。
- **修复：** 区分传输失败、本地校验和服务端拒绝；仅传输失败增加“写入结果可能未知 / 未自动重试”，断线通知保留已有错误。
- **若保留原行为：** 用户可能把缺失响应误当成未执行，直接重复写入。
- **验证：** 脚本化服务接收 `UNLINK` 后丢弃回复并关闭连接；界面保留明确提示，服务仅收到一次命令。另测本地校验和 `WRONGTYPE` 仍保留具体错误，不误报结果未知。

### 4. [P2] List 内容过滤词跨键残留

- **位置：** [`KeyDetailView`](../../Sources/RillApp/KeyDetailView.swift)。
- **作用：** 对已加载的 List 内容做本地过滤。
- **问题：** 在 `queue:jobs` 输入 `task:0001`，切换到两项均不匹配的 `queue:other`，旧过滤仍在，表头显示 2 / 2 而表格为空。过滤重置挂在临时集合内容视图上，旧内容销毁后无法观察到键变化。
- **修复：** 将清空过滤和成员选择的监听放到稳定的详情根视图，以选中键的变化为依据。
- **若保留原行为：** 用户会把被旧条件隐藏的成员误认为不存在。
- **验证：** 已在独立随机端口演示服务的原生窗口复现；修复后的窗口回归因 Mac 锁屏暂未完成，不修改用户实例。
