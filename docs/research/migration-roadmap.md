# Rill 迁移路线与验收标准

日期：2026-10-30。基线：`v0.1.0` / `b3bf2283ef96f6771c60f0f96fabea1c21a9c793`。本文保留迁移方案及其验收条件；当前实现状态见 [迁移实施与验证记录](implementation-log.md)。

依据 [七款客户端源码研究](source-deep-dive.md) 和 [65 个源码证据位置](upstream-sources.json)，建议先改善找键、加载和命令执行，再增加编辑深度。收益来自减少不必要的命令、给长任务设边界和保留用户状态；没有实测数据支持速度提升倍数。

## 优先级总览

P0 表示建议下一轮先做，P1 表示随后完善，P2 表示需要单独立项。这里不是故障严重程度。成本 S 为局部 UI/命令路径变化，M 为跨模型、调度与 UI 的变化，L 为连接协议或拓扑级工作；均是相对工作量，不是工期承诺。

| 编号 | 优先级 | 迁移内容 | 主要参考 | 对用户的收益 | 成本 / 依赖 |
|---|---|---|---|---|---|
| R01 | P0 | 精确键 / 模式查找 | Tiny、Medis、Insight | 粘贴键名即可直达，通配符含义清楚 | S；与 R05 的未知状态配合 |
| R02 | P0 | 有预算、可取消的扫描 | ARDM、Medis、Insight | 稀疏搜索及时返回，能停止和继续 | M；先定义取消与 socket 语义 |
| R03 | P0 | 可见行元数据、局部失败降级 | Insight | 先看到键，少查离屏信息，受限 ACL 仍可浏览 | M；依赖 R02、R05 |
| R04 | P0 | 复用独立工作台会话 | Tiny、Insight | 连续命令不反复建连，耗时含义准确 | M；会话隔离与失败状态 |
| R05 | P0 | 能力状态与错误分类 | Commander、Insight、P3X | 明白为什么不能用，减少整个界面报错 | M；R01/R03/R04 可分步共建 |
| R06 | P1 | 多层命名空间、稳定身份、原生键盘导航 | ARDM、Commander、Medis | 大量业务前缀更好找，切换后保留位置 | M；先完成 R02/R03 |
| R07 | P1 | 无损查看/草稿与受限转换 | Tiny、Medis、ARDM、P3X | JSON/编码数据好读，保存可预期 | M；保留现有 CAS 和 TTL |
| R08 | P1 | 参数帮助、保存搜索、会话状态恢复 | Insight、Medis、P3X | 高频重复任务少输入、少重新定位 | M；拆成独立小任务；工作台部分依赖 R04/R05 |
| R09 | P1 | 最新优先的 Stream 和成员过滤 | Tiny | 查最近事件更直接，集合查找有边界 | M；依赖 R02 的任务预算 |
| R10 | P1 | 可解释的诊断和有范围的分析 | Insight、P3X | 能判断慢查询和内存信息的含义 | M；依赖 R05；分析任务独立调度 |
| R11 | P1 | 版本化的单键完整导出与复制 | P3X、Medis | 数据可复查、可恢复，完整性看得见 | M；依赖 R02/R05；导入另行验收 |
| R12 | P2 | Hash 字段 TTL、GEO、模块按需扩展 | P3X、Insight | 扩大数据结构深度 | M–L；实际需求及服务器能力驱动 |
| R13 | P2 | 专用 Pub/Sub / Profiler 会话 | Medis、Insight | 实时排障 | L；依赖 R04；有界缓冲、生命周期必需 |
| R14 | P2 | 内建 SSH、Sentinel、Cluster | ARDM、Tiny、Insight | 安全访问远端和拓扑环境 | L；拆分阶段，独立协议/拓扑验收 |

建议执行顺序：R01 → R02 → R05 与 R03 → R04。完成这条路径并实测，再决定 R06–R11 的具体顺序；R12–R14 保持后置。P0 的范围是现有 standalone 工作流的质量，不默认增加持续监听和复杂运维操作。

## R01：精确键与模式查找

**现状：** [`RedisDatabase.scan`](../../Sources/RillCore/RedisDatabase.swift) 的搜索统一走 SCAN MATCH。已知完整键也要等扫描碰到它。

**方案：** 搜索框明确区分精确键和 Redis glob。精确模式按原始字节 TYPE/存在性定位，随后按需加载详情；单键缺失就是无结果。模式查询保持服务端 MATCH。命名空间跳转先转义字面前缀，收藏键可以不经当前扫描直接打开。

**验收：** 在含 10 万键的独立测试库中，定位已有/缺失完整键均不发 SCAN；请求数不随库大小增加。`a*b`、`a?b`、`a[b]`、反斜杠、中文、空白和二进制键具有无歧义的入口。TYPE 被拒绝或键在读取中消失时，分别显示权限状态或已不存在。

**提升如何测量：** 命令轨迹、首次详情时间、错误分类；不能将请求路径缩短直接换算成固定加速倍数。

## R02：让长查询及时交还控制权

**现状：** [`loadKeys`](../../Sources/RillApp/AppModel.swift) 每轮最多续扫 8 个空页，有代次检查和去重；没有直接面向用户的暂停/取消。COUNT 是提示，不能严格限制结果条数/字节。

**方案：** 扫描状态包含连接配置版本、DB、模式、类型、游标、去重集和待展示缓冲。区分单次 COUNT、本轮请求上限、墙钟预算、显示结果上限、累积字节上限。任一预算到达就保留游标并交还 UI；明确区分扫描结束、预算暂停、用户停止和失败。多出来的结果暂存，不能截断后丢失游标中尚未展示的数据。

取消需要先处理 [`RedisConnection.pipeline`](../../Sources/RillCore/RedisConnection.swift) 当前“Task 取消即关闭整条连接”的行为。建议先采用请求边界上的协作停止：UI 立即退出等待并丢弃旧代次结果，已发出的响应按顺序读完，随后不再续扫。若确需硬中断，应使用独立只读任务连接，并明确关闭范围。不能让停止搜索顺带中止编辑写入，不能留下未消费响应造成协议串线。

**验收：** 覆盖连续空页、重复键、COUNT 超出期望、键同时增删、切换 DB、快速替换搜索和断网。用户停止后 UI 立即响应，后续响应不得覆盖新搜索；正常网络下不再发起下一条 SCAN。稀疏模式到预算即暂停，保留续查能力；已过期和重复项不损坏计数。预算参数先使用保守内部值，通过实测调整，不先增加一排配置。

## R03：键名先到，屏幕需要什么再补什么

**现状：** 扫描取得 N 个键后立即发送 2N 个 TYPE/PTTL 命令；任何一项 `.checked()` 失败可使整批失败。

**方案：** 将原始键身份与可选元数据分开。先展示名称，随后对可见行和少量预取行批量加载所需列；类型筛选已提供可信类型时避免重复 TYPE。缓存按连接/DB/原始键隔离，过期时间和错误状态单独建模。后台结果按原始键 ID 和代次合并。编辑或刷新后失效受影响条目，隐藏列停止获取相应信息。

**验收：** 设 N=1000 个已获取键、V=40 个需要元数据的可见及预取键，未滚动时元数据命令数应随 V 而非 N 增长。单项 MEMORY/PTTL 被 ACL 拒绝时名称和其他可用数据仍能显示；缺失、永久、未知 TTL 分开。滚动时部分行命中缓存、返回顺序改变、搜索已切换等情况均不能把详情写到错误键上。

**收益边界：** 同样请求两列时，命令数量可从 2N 改为约 2V，这是静态工作量推导；实际首屏和网络收益要测量。不能把 pipeline 命令数直接当作往返次数。

## R04：工作台复用专用连接

**现状：** [`executeConsole`](../../Sources/RillApp/AppModel.swift) 每条命令都经过新建连接、可选 AUTH/SELECT、PING/INFO，再执行和关闭；显示耗时包括上述过程及格式化。

**方案：** 为当前工作台保留一条独立会话，由 actor 管理串行请求和正在建连的等待者。身份包含 profile、配置修订、DB 和用途；切库、改认证、断开、空闲回收和退出均有显式处理。浏览和工作台保持用途隔离。耗时用单调时钟区分连接准备、命令往返和结果展示，用户看得到首次连接成本。

**验收：** 同一会话连续 20 条命令只发生一次正常建连/认证初始化；连接断开后的下一次执行可重建。快速并发触发只能创建一个该用途的会话；不影响浏览所选 DB。只读、生产确认、事务/阻塞/订阅/管理命令限制继续有效。写入超时仍标记结果未知，不能为了重建会话自动重放写入。

## R05：能力不足也要能理解、能继续

**方案：** 在实际命令响应上区分可用、版本/命令不支持、ACL 拒绝、代理限制和暂时失败。COMMAND/INFO 可作为能力线索；无法读取时使用离线目录与已有结果，不要求用户为了浏览授予管理员权限。只读准入仍由 Rill 的明确命令/子命令策略决定，动态目录不能自行放宽执行权限。诊断未知值不伪装成零值。

**验收：** 分别测试禁用 COMMAND、INFO、MEMORY、PTTL、SCAN TYPE 的合成 ACL 账户及响应模拟。可行的独立工作流继续使用，受限入口解释原因。未知模块命令在只读模式拒绝；BITOP、XREADGROUP、CONFIG 写子命令和其他现有禁用命令不能因目录变化被开放。版本号高但命令不可用、版本字符串异常，也应正常降级。

需要落点：[执行策略](../../Sources/RillCore/Models.swift)、[连接和元数据](../../Sources/RillCore/RedisDatabase.swift)、[错误与异步状态](../../Sources/RillApp/AppModel.swift)。

## R06：原生命名空间与工作位置

**方案：** 使用原始键字节构建命名空间，文件夹与真实键使用显式不同的节点身份；可配置分隔符，默认冒号。仅展开可见分支并保持 AppKit 键盘选择、焦点和辅助功能。状态按连接和 DB 保存，键失效时有合理回退。树建立和排序移出主线程前先测量，避免每页重建全树。

**验收：** `a`、`a:b`、`a::b`、`a:`、含字面通配符、不同字节但同样显示文本的键可同时存在并正确操作。文件夹不会被当成真实键删除/重命名。上下键、展开、回车查看、⌘F、菜单操作不会抢走文本编辑器的快捷键。10 万已加载键下测量构建时间和内存；超出内部容量时明确提示范围，不能称为全库完整树。

## R07：查看舒服，保存仍以原值为准

**方案：** 保持三份语义：读取原始字节、当前显示表示、用户草稿。格式切换不改变读取原值；显式格式化只改变草稿，原始值仍用于冲突检查。JSON/Hex 先完善，随后可小范围加入 base64/gzip 等可逆转换；保存前反向转换并预览写入后的字节长度。解码失败不能变成空值；无法无损逆向的展示只读。

转换和高亮需要后台预算与代次检查。压缩限制输出大小、膨胀比和时长。先用离线分片响应和大文本测量 RESP 重复解析、高亮全篇重算等本地热点，再选择增量解析、缓存正则或局部高亮，不预设重写整个编辑器。

**验收：** 格式切换不产生写命令；空值、非法 JSON、非 UTF-8、NUL、压缩损坏、超大解码结果均有稳定状态。保存失败/冲突保留草稿；保存前已变化或过期的值不被覆盖。TTL 继续保留。截断预览不能保存成完整值；Stream 原始字段对和二进制身份不受格式化影响。

**测量：** 大文本输入延迟、主线程最长任务、分片解析耗时和峰值内存。当前没有这些实测结果，不据此声称首版已经出现性能故障。

## R08：减少每天重复的动作

分成三个可独立交付的小任务：保存连接/DB 维度的搜索模式和当前工作位置；离线参数语法、子命令和参数占位提示；内存历史搜索、去重与再次执行。可先恢复显示偏好，避免自动执行命令或自动丢弃脏草稿。后续若增加历史持久化，应为显式选择，默认继续不落盘结果和敏感参数。

**验收：** 断网时命令帮助可用；服务端 COMMAND 被拒绝仍能执行现有允许命令。补全保留引号和转义，不误提交命令。切换连接/DB 不串用选择、结果、搜索和解码偏好。重开视图后可以返回原位置；消失的键不会打开另一个键。所有编辑快捷键遵循原生焦点行为。

## R09：Stream 与集合查找

**方案：** Stream 提供最新优先、方向和 ID 区间，使用排他 ID 续页，保留原始字段数组。Hash/Set/ZSet 过滤优先使用相应扫描能力；List 和内容搜索明确“已加载内容”或“有预算的服务端读取”范围。每个成员扫描状态绑定连接、DB、原始键、模式与方向。不要为了做本地过滤先读全量。

**验收：** 连续翻页无边界重复；页面间新增/删除条目、空页和刷新时状态正确。重复字段名及字段顺序保持；过滤预算耗尽与真正无结果分开。字段 TTL 等额外命令仅在能力确认并需要显示时请求。

## R10：诊断有解释，分析有范围

**方案：** 先完善 Slowlog 单位、时间、请求条数和空结果解释；有权限时可通过专用只读路径获取服务端阈值，没有权限就显示未知。不要把空列表解释为服务器从未慢过。INFO 可提供用户主动开启的短窗口趋势，离开页面停止采样；重启或计数器回退时重置差分。

第二步再做按需内存分析，明确样本数、实际扫描预算、已完成范围和数据时间；每批元数据有大小上限。到预算时真正停止继续扫描。采样出的较大键只代表本次范围内排序，不叫全库 Top，也不把 SCAN 的确定性顺序样本包装成随机统计推断。

**验收：** 覆盖无慢查询、阈值不可读、时钟单位、INFO 缺项、Redis 重启和 ACL 拒绝。切页面后计时器/任务释放。分析期间键浏览仍可响应；扫描请求数受预算控制，取消后不再续扫。只读诊断不得执行 CONFIG SET、SLOWLOG RESET 或清库命令。

## R11：先把一个键完整、明确地带走

**方案：** 保留当前页导出，同时新增独立的“完整导出此键”。格式显式包含版本、类型、原始键 base64、字段/成员编码、分值、Stream 原始字段对、采集时间、过期策略及 `complete` / 失败原因。String 按范围分块，其他类型有预算地分页；COUNT 不能代替字节限制。失败文件不能表现为成功完整备份。

变化中的 Redis 读取不是一致性快照，单键分段读取期间也可能改变。格式需要声明这一点；导出前后的类型/长度检查只提供变化线索，不能证明强一致。TTL 恢复要明确按剩余寿命还是绝对时间，不能无意延长已导出数据的生命。Stream 消费组和 PEL 等状态不在普通条目导出的完整性承诺内。

单键复制可优先探测服务端 COPY 能力，遵守目标存在和写入确认规则；DUMP/RESTORE 回退应独立验证兼容性与 TTL，先不扩展到跨实例迁移。

**验收：** 全类型二进制往返、空字段、重复 Stream 字段、分值精度、永久键、导出中途过期/变化、取消、磁盘写失败。导入覆盖策略必须显式选择并复用只读/生产保护。未完成导入验收前，导出能力不能描述为“已经支持迁移”。

## R12–R14：保持明确的下一阶段边界

- **R12：** 先确认真实需求，再按类型添加能力。Hash 字段 TTL、模块读取与编辑分别验收；未知模块保留可理解的只读状态。避免先做通用插件平台。
- **R13：** 每个监听用途使用独立连接；有界环形缓冲、聚合刷新、丢弃计数、停止按钮和窗口关闭回收缺一不可。断线重连后的事件间隙必须可见；不能默认持续记录生产流量。
- **R14：** SSH 先做主机指纹/known_hosts 与密钥认证；TLS 自定义 CA、客户端证书和 SNI 分开验证。Sentinel 发现、故障切换、Cluster 槽路由、MOVED/ASK、每主节点扫描游标、节点地址映射及重分片都要有自己的测试。SSH 隧道只转发入口并不自动完成拓扑支持。

## 实现前准备的可复用验收数据

后续测试应自行启动仅监听本地的新 Redis 实例，不访问或清空已有数据库。建议准备：小型全类型/二进制数据集；10 万键的精确与稀疏搜索数据集；单个大字符串和大集合；分权限 ACL 账户；代理延迟/分包/断线响应。跨版本测试覆盖最低目标和当前已验证版本，记录版本与硬件条件。

每项任务只增加与其风险直接相关的检查。性能基准统一记录数据量、命令轨迹、网络延迟、首屏时间、取消行为、主线程和内存，不以应用包大小代替运行性能。源码静态推导与真实测量分开写入验证记录。

路线图初稿编写时沿用 22 项首版测试结果，见 [既有验证记录](../validation.md)。后续功能实施、自动测试与原生验收结果统一记录在 [迁移实施与验证记录](implementation-log.md)。
