## R01：精确键查找

- 增加“模式 / 精确键 / Hex 键”三种明确入口，精确键不解释 glob、转义或空白；Hex 支持原始二进制和空键。
- 通过 TYPE/PTTL 定位键，匹配后自动打开详情。收藏菜单直接按原始字节定位，不要求先扫描到该键。
- TYPE 权限错误保留为错误，不伪装成键不存在。查询中已删除的键返回无结果；连接仍保持响应对齐。
- 新增 3 项自动测试。独立随机端口 Redis 写入 100,000 个键，精确已有/缺失查询共执行 2 次 TYPE、2 次 PTTL、0 次 SCAN；覆盖字面通配符、中文、空白、反斜杠、空键、二进制和受限 ACL。
- `swift test`：25 项，0 失败、0 跳过；`scripts/build-app.sh`：Release 构建及签名检查通过。
- 原生 UI 在独立演示实例上确认：选择精确键、提交 `app:settings` 后只显示该键并自动打开 JSON 详情。没有连接已有 6379。

验证环境沿用 [首版环境](../validation.md)。上述命令数量是本次真实集成测试结果，不是产品之间的性能排名；远端弱网和最低系统版本未在此项重新验证。

## R02：扫描预算与取消

- 增加独立扫描会话，保存已提交查询、游标、去重集及超页缓冲。修改搜索框但未提交不会污染续扫条件。
- 每轮最多显示 200 个键、8 次 SCAN、500 ms 协作时间预算；全轮最多保留 10 万个唯一键或 16 MiB 原始键名字节。时间预算在响应边界检查，不承诺中止服务端已执行命令；网络仍受连接超时约束。容量达到时提示缩小范围，不标为完整扫描。
- “停止”/Esc 只停止继续请求，已发出的回复读完并保留；继续时使用缓冲与原游标。新查询切换代次，旧回复不能写入新结果。
- 新增 5 项确定性会话测试和 1 项真实 Redis 测试，覆盖空页、重复、超页缓存、请求/时间/容量预算及暂停。650 个键续扫无丢失、无重复，停止后同一连接 PING 正常。
- `swift test`：31 项，0 失败、0 跳过；Release 构建和签名通过。
- 原生 UI：在合成演示实例上使用 CLIENT PAUSE 制造延迟，Esc 后出现继续扫描入口且连接保持；加载期间将 `not-found:*` 替换为 `app:*`，最终只显示两个 app 键，未被旧结果覆盖。

## R05：能力与错误降级

- 服务端错误区分权限、认证、命令不支持、类型变化及集群重定向，保留原始错误。实际请求结果记录为连接能力；不根据版本号推断可用性，也不改变命令准入策略。
- TTL 和库总数允许未知；可选元数据逐项保留错误。TYPE 不可读时仍能列出扫描键名；打开详情/精确查找则明确说明无法判定类型。PTTL/MEMORY 不可读时允许读取获准访问的值，未知 TTL 不显示永久。
- SCAN TYPE 的语法/选项不支持响应会触发有预算的普通 SCAN + 类型筛选回退；权限错误不会触发绕行，也不回退到 KEYS。回退请求计入 R02 的请求预算，初始游标为零的待重试状态不会误报扫描完成。
- 服务器页展示观察到的能力及错误原因；INFO 不可用时未知指标和持久化状态不显示为零或关闭。
- 全量 `swift test`：36 项，0 失败、0 跳过；补充 SCAN 禁用后精确查找仍可用的断言单独复验。覆盖 INFO/COMMAND/PTTL/MEMORY/DBSIZE/TYPE/SCAN 权限、代理不支持 TYPE、连接响应对齐和只读策略。
- Release 构建/签名通过。原生受限演示连接验证：16 个键可见、键总数未知、JSON 内容可读、TTL 未知且可查看 NOPERM 原因；服务器页正确展示受限能力。没有修改任何已有 Redis 实例。

## R03：可见行元数据

- 浏览扫描先返回原始键名；元数据通过 AppKit clip view 的实际可见区域触发，60 ms 合并、每批最多 64 行，隐藏类型/TTL 列后不请求该列。仅依赖 SwiftUI onAppear 会把预创建行当成可见行，因此使用原生可见性检测。
- 行跟踪按视图实例和查询代次区分，旧实例销毁不能移除新实例的可见状态。结果按原始键 ID 合并；查询切换丢弃旧回复。过期键移出列表，脏草稿对应的键保留并标记不存在。
- 已有类型过滤结果免查 TYPE；可见行元数据有缓存，列重新启用时只请求该批缺少的信息。权限错误保留为字段状态，不反复自动重试。无 SCAN TYPE 的兼容路径仍需要检查扫描批次的类型才能筛选，但不预取 TTL。
- 新增真实集成测试：扫描 1,000 个键名，0 次 TYPE/PTTL；给 40 个键补两列时各 40 次。隐藏列、已知类型均验证没有相应额外命令。全量 `swift test`：37 项，0 失败、0 跳过。
- 原生实测：首批 200 个键中只有 8 个可见键触发元数据；滚动新增 10 组请求，返回原位置计数不增加。独立 QA 副本另一轮首屏 9 组；隐藏 TTL 后出现 11 个新行，TYPE 从 9 增至 20，PTTL 保持 9。滚动中发现并修正的一行漏载已重新验收。
- Release 构建/签名通过；构建脚本支持指定独立输出目录，并包含完整文档目录。用户正在使用的 Rill 窗口和独立演示实例保留，后续验收使用 Rill QA。

## R04：独立工作台会话复用

- 工作台 actor 串行处理请求，复用专用连接；配置、DB 或认证变化时重建。连接准备中的请求合并为一次建连，空闲 5 分钟回收。浏览会话继续独立。
- 使用单调时钟区分准备耗时与完整命令往返；结果只格式化一次。连接健康检查不发额外 PING，正常复用不会重复 AUTH/SELECT/INFO 初始化。
- 检测到断线后，下一条命令重建；本次失败的写入不重放，并明确提示结果可能未知。关闭会话会取消建连和所有排队的旧请求，生产确认同时核对当前连接代次。
- 新增 6 项测试：20 条连续命令只新增 1 条连接；20 次并发触发仅 1 次准备；浏览 DB0 与工作台 DB1 隔离；服务端错误后可继续复用；空闲回收、认证变化、只读/会话命令限制、已检测断线重建。模拟丢写回复只收到 1 次 SET，下一条独立命令才重建；关闭建连时排队旧 SET 均未发送。
- 全量 `swift test`：43 项，0 失败、0 跳过；独立输出的 Release 构建及签名通过。
- 原生 Rill Console QA：第一条 PING 显示“新建连接、准备、命令往返”，第二条显示“复用连接”，两个结果均为 PONG。用户原有窗口未替换。

## R06：多层命名空间

- 树身份来自原始键字节，文件夹使用与键不重叠的标识。支持完整多层、空分段、键本身也是前缀、自定义多字节分隔符；二进制标签有 HEX 标记，与相同显示文本的普通键区分。
- 文件夹只提供复制/前缀查询；键操作仍绑定真实叶节点。前缀查询对 glob 特殊字符转义。计数只代表已加载键。键名预览有字节限额，保持 UTF-8 边界；原始身份和复制数据不截断。
- 树在后台构建，元数据变化不重建；切换查询取消旧构建并检查代次。层级/文件夹数量/前缀存储有上限，达到上限后保留键的完整后缀，不丢弃键。
- 分组、分隔符和展开选择按连接 ID + DB 保存；合成 UserDefaults suite 验证不同连接/DB 不串用，原生存储检查及 Keychain 合成 CRUD 通过。
- 全量 `swift test`：48 项，0 失败、0 跳过，包含 5 项命名空间专项。最近一次全量中的 10 万键 Debug 构建约 923.9 ms，测试进程驻留内存变化约 25.3 MiB。此数值不是完整界面峰值，也不是产品对比性能排名。
- Release 构建/签名通过。原生界面确认：真实 a 与 a: 前缀可共存、空分段和空后缀可见、二进制/普通相同显示名分开、右方向键展开嵌套 branch。后续叶节点选择、分隔符弹窗和跨库界面恢复因 Mac 锁屏暂未复验；存储隔离已自动验证。

## R07：无损值编辑与受限转换

- 原始读取字节、解码结果和文本草稿独立保存。文本/JSON/Hex 切换不改原值、不发送写命令；切换解码器或离开脏草稿仍需确认。解码失败保留原始 Hex，二进制及截断内容只读。编辑器按键/编码身份重建，避免跨键撤销历史。
- 手动选择原始、Base64、Gzip、Base64 → Gzip；保存按相反顺序编码，以读取的原始字节做 CAS，保留 TTL。写入前显示编码后的字节数和改变范围；失败保留草稿。Base64 严格验证，Gzip 校验 CRC、拒绝尾随/多段，限制输入/输出 1 MiB、膨胀比 1024、每次压缩转换 200 ms。
- JSON 解析/格式化保留数值原词法、字段顺序、重复字段和转义，不经浮点数转换。显式格式化只改变草稿。转换、Hex 和高亮匹配移到后台并检查代次；高亮缓存正则，相同内容/格式不重复匹配，超过 20 万 UTF-16 单元关闭着色。
- 先测量再修改：增量 RESP 分帧保留不完整响应位置，仅在完整帧后构建值；保持原有 32 MiB、数组元素和嵌套限制。新增逐字节/随机分片、流水线、二进制、空/嵌套帧及恶意长度测试。Hex 改用固定查表输出，金样保持原格式。
- `swift test`：58 项，0 失败、0 跳过；包含真实 Redis 的四种编码写回、TTL、冲突、键消失验证。Release 构建/签名通过；原生转换、输入延迟及撤销验收因 Mac 锁屏待复验。
- 同机 `swiftc -O` 离线单次基准：1 MiB bulk / 1 KiB 分片，旧解析本轮 10.54 ms（前测 14.50 ms），新分帧 0.76 ms；10,000 × 80 B 数组（870,008 B）分片，旧 466.05 ms（前测 465.80 ms），新 1.08 ms。Hex 1 MiB 从前测 1078.69 ms 到本轮 10.32 ms。可用 `scripts/benchmark-values.swift` 复测。这些是合成局部耗时，不代表网络、整机输入延迟或峰值内存收益；未完成 Instruments 主线程/峰值测量。

## R09：最新 Stream 与有范围的成员过滤

- Stream 默认 XREVRANGE 最新优先，支持方向和 ID 范围，续页使用排他 ID；不把重复字段变成字典。响应中的字段对先验证，再保留原始数组供编辑/导出使用。
- Hash/Set 使用 HSCAN/SSCAN MATCH，带过滤的 ZSet 使用 ZSCAN MATCH 并标明游标顺序；未筛选 ZSet 继续按分值读取。List 只过滤已加载内容，入口明确范围。显示数 / 总数中的总数是此键成员总量，并非筛选后的总量。
- 独立成员会话冻结原始键和查询，每批最多 200 行、8 次分页、500 ms 响应边界预算；累计 1 万成员 / 16 MiB。超过一页缓存、原始身份去重、空页及时返回，容量限制明确标为不完整。停止会消费当前回复并保留结果，不取消共享浏览 socket。
- 查询/键切换检查详情代次；键列表刷新同时核对详情选择代次，避免晚到的恢复读取覆盖新选择。
- 4 项专项覆盖超页、去重、空页预算、容量、协作暂停及边界校验；真实 Redis 验证 450 条 Stream 的双向/排他范围及分页间新增删除，重复字段/二进制数组保持；600 成员的 Hash/Set/ZSet 分别过滤得到 300 个唯一匹配项，分值字符串保持精度。全量 `swift test`：68 项，0 失败、0 跳过；Release 构建与签名通过。原生界面仍待 Mac 解锁。
- 命令依据 [XREVRANGE](https://redis.io/docs/latest/commands/xrevrange/)、[ZSCAN](https://redis.io/docs/latest/commands/zscan/)；排他 Stream ID 需要 Redis 6.2+。SCAN 的成员结果不承诺一致性快照或稳定顺序。

## R10：可解释诊断与有范围的内存分析

- 慢查询显示读取时间、最近 50 条、当前记录数/容量、微秒到毫秒的单位及服务端记录阈值。阈值 -1/0 分别解释为关闭/记录全部；CONFIG GET 固定配置项不可读时保留可读 SLOWLOG，明确阈值未知。空列表不推断“从未慢过”。工作台仍禁止 CONFIG，内部路径只读两个固定参数。
- 用户主动开启 INFO 趋势，独立连接每 2 秒采集一次、最多 60 点；内存和操作速率分开展示，速率基于本地单调时钟与累计命令差分。缺项、计数回退、run_id 或 uptime 重启迹象会断开曲线。离开页面、断开连接和停止按钮回收任务与专用连接。
- 按需内存分析再开专用连接：最多 8 次 SCAN、1,000 键、1 MiB 键名、5 秒请求边界预算，每批最多 64 个 MEMORY USAGE。到预算真正停止请求；可随时停止并保留已测范围，浏览连接保持独立。显示已查/可用/未知、SCAN 次数、采集时段及“本次范围内较大的键”；不称全库 Top，不把顺序样本视为随机抽样。
- 4 项专项验证趋势差分/缺项/重启、60 点上限、请求/键/时间预算、批量限制和取消后不再读取；真实 Redis 验证受限 CONFIG 仍能读取 SLOWLOG，以及 129 键（含 2 MiB String）的只读内存分析、较大键排序和浏览连接可用性。全量 `swift test`：74 项，0 失败、0 跳过；Release 构建与签名通过。原生曲线/切页生命周期仍待 Mac 解锁。
- 依据 [INFO](https://redis.io/docs/latest/commands/info/) 与 [MEMORY USAGE](https://redis.io/docs/latest/commands/memory-usage/) 官方参考；内存值是 Redis 估计值，分段扫描仍不是一致性快照。
